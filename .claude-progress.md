## Phase 0 — Setup ✅ (2026-08-19)

- Laravel 12 + Breeze (Blade stack) scaffolded at repo root.
- MySQL `blood_connect_ju` created (`utf8mb4` / `utf8mb4_unicode_ci`), `.env` wired to it, `ALLOWED_EMAIL_DOMAIN=juniv.edu` added as a placeholder env var (per Section 11, needs the real JU domain confirmed later).
- Design system ported from the reference repo (`salman1237/blood-connect-ju`, `src/styles.css`) into `tailwind.config.js` + `resources/css/app.css`. Reference uses Tailwind v4's CSS-first `@theme`; this project's Breeze scaffold ships Tailwind v3, so the OKLCH tokens are stored as bare `L C H` triplets and wired through `oklch(var(--x) / <alpha-value>)` so Tailwind opacity modifiers (`bg-warning/20`, etc.) still work. Dark mode intentionally not ported — the brief only specifies a light theme.
- Font: Public Sans (Google Fonts), loaded in both layout heads.
- Shared component library mirroring the reference's `brand.tsx`: `x-logo`, `x-language-toggle` (decorative Alpine toggle, same as the reference prototype — real session-persisted switching lands in the localization phase), `x-blood-drop`, `x-urgency-badge`, `x-status-pill`, `x-verified-badge`, `x-section-title`, plus `x-icon` (inline Lucide icons, exact paths pulled from the `lucide-static` package) and `x-button` (not in the reference's `brand.tsx` — added because nearly every remaining phase needs consistent buttons; sized at a floored 44px tall on every breakpoint per the brief's hard touch-target requirement).
- `layouts/guest.blade.php`: minimal public shell (landing + auth pages each build their own header/structure, matching how the reference's `Landing` and `AuthShell` differ from each other).
- `layouts/app.blade.php`: authenticated shell matching `app-shell.tsx` — fixed sidebar ≥ `lg`, fixed bottom nav < `lg`, sticky header with title/subtitle + language toggle + avatar initials. Nav links are guarded with `Route::has()` so the shell doesn't break as routes are added phase by phase; unbuilt destinations (Donors, Alerts, Ranks, Settings, Verifier queue, Admin, Post request) simply don't render as links yet.
- `landing.blade.php`: exact hero copy, stats row, live-requests preview (static illustrative data matching the brief's Section 9 seed examples), feature strip, and footer line ported verbatim from the reference's `routes/index.tsx`.
- Breeze's default top nav (`layouts/navigation.blade.php`) and its unused dropdown/nav-link components removed — superseded by the new app shell. `dashboard.blade.php` and `profile/edit.blade.php` updated to the new `<x-app-layout title="..." subtitle="...">` contract so the app boots end-to-end; their actual content/redesign is Phase 2 (profile) and Phase 3 (dashboard feed) work.
- Auth pages (login/register/forgot/reset) are **still Breeze's unstyled defaults** — restyling them to the brand shell (`x-auth-card`, matching `AuthShell` from the reference) is explicitly Phase 1 work, done together with the domain-restricted signup and role selection changes to avoid redoing the same views twice.
- Laravel Pint added as a dev dependency; `.github/workflows/tests.yml` added (PHP 8.2, sqlite in-memory for speed, `npm run build` so `@vite` resolves, `pint --test`, `php artisan test`).
- Verified: `npm run build` succeeds, compiled CSS contains the ported OKLCH tokens, `php artisan migrate` succeeds against `blood_connect_ju`, `php artisan test` — 25/25 passing, dev server smoke-tested (`/`, `/login`, `/register` all return 200, landing page renders the expected copy).

**Not done yet (intentionally, later phases):** role column/middleware, donor profiles, blood requests, matching, trust & safety, engagement, notifications, admin dashboard, real localization, seed data.

## Infrastructure — production hosting + CI/CD ✅ (2026-08-19)

- **Live at https://blood.deshlet.com** — cPanel subdomain on the `skoder` shared hosting account, docroot `public/`, PHP 8.2 (`ea-php82`), Node 22 (via nvm, installed alongside the account's existing Node 18 default — not changed globally).
- Production MySQL: `skoder_blood_connect_ju` (`utf8mb4_unicode_ci`), dedicated DB user with least-privilege grants scoped to that one database.
- `APP_ENV=production`, `APP_DEBUG=false` explicitly set — non-negotiable given what this account went through (see below).
- Deploy key (`ed25519`, no passphrase) authorized in cPanel's SSH access; stored as an encrypted secret (`SSH_PRIVATE_KEY`) on the GitHub repo alongside `SSH_HOST`/`SSH_PORT`/`SSH_USER`/`DEPLOY_PATH`.
- `.github/workflows/deploy.yml`: on push to `main`, waits for the `tests` workflow to pass first (`lewagon/wait-on-check-action`), then SSHes in (`appleboy/ssh-action`) and runs `git reset --hard origin/main` → `composer install --no-dev` → `npm ci && npm run build` → `migrate --force` → cache rebuild. Deploys never happen on a red build.

### Security detour (2026-08-19) — relevant context for anyone touching this hosting account

Before any of the above, discovered the `skoder` cPanel account (which hosts ~35 unrelated sites, not just this project) had been compromised since **2026-06-10** via a Laravel Ignition RCE (CVE-2021-3129 class — `APP_DEBUG=true` + `ignition` package exposed in production on multiple independent Laravel deployments on the account). Confirmed via access logs (real `200` responses to `POST /_ignition/execute-solution`, not just blocked probes). Because every site on the account shares one Linux user, that one breach gave account-wide filesystem access, leading to four separate mass-webshell-drop waves (Jul 17, Aug 8, Aug 16, Aug 17) — and the account owner had already found and cleaned this twice before (Aug 8–9, Aug 12) without closing the actual hole, so it kept coming back.

Remediated as part of this session:
- Flipped `APP_DEBUG` false on the 8 sites still exposed.
- Removed 747 individual webshell files + 657 entire malicious directory trees (~1,400 objects total) across the account, using content-signature + creation-timestamp verification per file (not blind pattern deletion — two files that looked suspicious by heuristic turned out to be genuine Laravel front controllers and were left alone).
- Evidence archived to `~/incident_evidence/malware_removed_20260819_044322.tar.gz` before deletion.
- **Not done, and outside this project's scope**: full credential rotation account-wide, patching/redeploying the other ~30 unrelated sites, confirming with whoever else has access to this account. Flagged to the user directly — this is bigger than Blood Connect JU and belongs to the account owner's broader incident response, not something to silently fold into this repo's history.
